# 仕入れ判定ツール 構想（v0.1）

Grok Bot が Discord に流す情報を自動で拾い、Keepa・Amazon の実データで裏取りし、Claude が「買い / 保留 / 見送り」を判定して Discord に返す。人がやるのは最終確認と仕入れだけにする。

---

## 0. 一言でいうと

```
Grok（X を読む）→ Discord #grok-raw に投稿
   ↓ 自動
Python bot が投稿を拾う → コード（JAN/ASIN）を抽出
   ↓ 自動
Keepa / SP-API で相場・ランキング・手数料を取る
   ↓ 自動
ルール計算（利益率・粗利・月販）＋ Claude の総合判断
   ↓ 自動
Discord #judge に「買い / 保留 / 見送り」＋理由＋DESK リンクを投稿
   ↓ 人
✅ 仕入れた / ❌ 見送った をリアクションで記録 → 判定精度を週次で振り返る
```

Grok は「何が・どこで・いつ」を拾うのが得意、数字の裏取りは苦手。だから **数字は API から取り、判断は Claude、情報収集は Grok** と役割を分ける。

## 1. いまあるもの（再利用する資産）

| 資産 | 場所 | 使い方 |
|---|---|---|
| Grok Bot チーム仕様 v0.2 | ブランチ `claude/grok-bot-spec` の `grok-bot.md` | 5 体の役割と「1 件に必ず `DESK: <コード>` を付ける」ルールがすでにある。出力形式をそのまま解析の入力にできる |
| Discord 在庫ボット | ブランチ `claude/discord-book-inventory-bot-tm2q4h` の `bot/` | discord.py で常駐、Webhook 投稿、Embed 生成、Keepa グラフ、SP-API（`bot/spapi.py`）の口がある。ここに「Grok 投稿を監視して判定する」機能を足す |
| せどりDESK | `index.html` | 最終確認用の串刺し検索。判定結果に `index.html?q=<コード>` のリンクを付けて 1 タップで裏取りに飛ぶ（grok-bot.md の提案 A） |

ゼロから作るのではなく、Discord ボットに **1 つのリスナーと 1 つの判定モジュール** を足すだけで骨格ができる。

## 2. 構成要素

### A. 入口：Discord のチャンネル設計

| チャンネル | 役割 | 書くのは |
|---|---|---|
| `#grok-raw` | Grok Bot ①〜③ の出力を貼る場所（手動コピペ、または Grok 側の自動投稿） | 人 / Grok |
| `#judge` | 判定結果が自動で流れる | bot |
| `#rules` | ルール監視 Bot ④ の出力（判定とは別に流す。規制対象の商品名は判定にも渡す） | 人 / Grok |
| `#log` | 解析できなかった投稿、API エラー | bot |

Grok 側は既存仕様のまま。変更は不要。

### B. 取り込み：投稿を構造化する

1. `#grok-raw` に新規投稿が来たら bot が拾う
2. 正規表現で `DESK: <コード>`、価格、店名、信頼度（A/B/C）、情報源 URL を抜く
3. 正規表現で取れない崩れた投稿は Claude に「この文章から商品情報を JSON で抜いて」と渡す（構造化出力を使うので形は保証される）
4. コードが無い件は grok-bot.md のルール通り落とし、`#log` に理由を書く
5. 同じコードが 24 時間以内に来たら重複として束ねる（情報源が増えれば信頼度を上げる）

### C. 裏取り：数字を API から取る

| データ | 取得元 | 判定に使う項目 |
|---|---|---|
| Amazon 現在価格（新品 / 中古、FBA / 自己発送） | SP-API `getItemOffers`（`bot/spapi.py` に既存） | 想定売値 |
| 手数料・FBA 配送料 | SP-API `getMyFeesEstimate` | 利益計算の実額（grok-bot.md の「15% 仮置き」を実数に置き換える） |
| ランキング推移、90 日の価格推移、出品者数、ランキング降下回数 | Keepa API（有料） | 月販の推定、価格下落トレンド、ライバル増加 |
| メルカリ売切れ相場 | 公式 API なし。初期は Grok の値をそのまま「要確認」で使う | 参考値 |
| 定価・JAN↔ASIN 変換 | Keepa（JAN 検索）/ SP-API Catalog | コード統一 |

Keepa が無い間は SP-API の現在価格だけで動かし、月販は「未取得」として判定の自信度を下げる。

### D. 判定：ルール計算 ＋ Claude の総合判断（2 段階）

**第 1 段：ルール計算（Python、決定的）**

```
粗利 = 想定売値 − Amazon 手数料 − FBA 配送料 − 仕入れ値
利益率 = 粗利 ÷ 仕入れ値
月販見込み = Keepa のランキング降下回数（30 日）
```

| 判定 | 条件（grok-bot.md のしきい値を踏襲） |
|---|---|
| 買い候補 | 利益率 15% 以上 かつ 粗利 1,000 円以上 かつ 月販 10 個以上 |
| 保留 | 上の 1 つが欠ける |
| 見送り | 赤字、または月販 3 個未満 |

**第 2 段：Claude の総合判断（ルールだけでは拾えない要素）**

ルール計算の結果と生データを Claude に渡し、次を見てもらう。

- 価格下落トレンド（90 日で売値が落ち続けていないか）
- 出品者数の急増（プレ値が崩れる前兆）
- 真贋・出品規制・転売禁止規約のリスク（`#rules` の内容と照合）
- 季節性・話題性の持続（トレンド Bot の「言及数」が一過性か）
- Grok の情報の信頼度（A/B/C と情報源の数）

出力は構造化（JSON 固定）。

```json
{
  "verdict": "買い | 保留 | 見送り",
  "confidence": 0.0〜1.0,
  "reasons": ["3 行以内"],
  "risks": ["あれば"],
  "max_buy_price": 仕入れ上限（この値段までなら買い）,
  "check_in_desk": ["DESK で人が確認すべき項目"]
}
```

ルールの判定と Claude の判定が食い違ったら「保留」に落とし、理由に両方を書く。安全側に倒す。

### E. 出力：`#judge` への投稿

1 件 1 Embed。見た目は在庫ボットの Embed と揃える。

```
🟢 買い（自信 0.82）  PS5 Pro 本体
JAN 4948872417044  ヨドバシ.com 119,980円（信頼度A・3ソース）
売値 134,800（FBA 新品最安）/ 手数料 10,784 / 配送料 1,040
粗利 約 3,000 / 利益率 2.5% / 月販 推定 45

理由: ランキング安定、出品者 12→14 で微増、90 日で価格横ばい
注意: 粗利は薄い。仕入れ上限 118,000 円
DESK で確認 → https://.../index.html?q=4948872417044
[Keepa グラフ]
```

リアクション: ✅ 仕入れた / ❌ 見送った / 🔁 再判定（価格が変わったとき）

### F. 記録と振り返り

- 全判定を `data/judgments.jsonl` に保存（入力・API の数字・Claude の判定・人のリアクション）
- 週 1 回、「買いと出したものの実売」「見送ったものの後の相場」を照合してレポート（これも Claude に書かせる）
- しきい値（15% / 1,000 円 / 10 個）はここで調整する。最初から正解を狙わない

## 3. 「Claude Code で自動解析」の置き方

やり方は 2 つ。**推奨は 1**。

| 方式 | 中身 | 向き不向き |
|---|---|---|
| **1. bot から Claude API を呼ぶ（推奨）** | Python の Discord bot 内で Anthropic SDK を使い、投稿が来た瞬間に判定 | 即時。常駐している bot にそのまま載る。Discord との接続も既存のまま |
| 2. Claude Code のルーティンで定期解析 | この環境の Routine（スケジュール実行）で毎朝 `#grok-raw` をまとめて読み、朝レポートを作る | Discord を直接読めないので、bot が投稿をファイルに溜めて渡す経路が別に要る。朝の「今日狙うもの 5 件」のまとめには向く |

まず 1 で即時判定を作り、慣れたら 2 を「毎朝 7:00 の精査・レポート Bot ⑤」の自動化として足す。

使うモデルは `claude-opus-5-5`（既定）。判定 1 件あたりの目安は入力 3,000 トークン・出力 500 トークン程度。

| 件数 / 日 | 月額の目安 |
|---|---|
| 20 件 | 約 2 ドル |
| 50 件 | 約 3〜4 ドル |
| 200 件 | 約 13 ドル |

Keepa の月額の方が高くつく。Claude の費用は気にしなくてよい規模。

## 4. 進め方（段階）

| 段階 | やること | ゴール |
|---|---|---|
| **0. 手動で型を作る（1 週間）** | Grok の出力を `#grok-raw` に貼る → 自分で DESK で裏取り → 「買い / 見送り」と理由を `#judge` に手で書く | 判定の正解データが 20〜30 件できる。Claude に渡すプロンプトの材料になる |
| **1. 解析だけ自動化** | bot に `#grok-raw` リスナー追加。コード抽出 → SP-API で価格・手数料 → ルール計算 → `#judge` に数字だけ投稿 | 数字を手で調べる時間がゼロになる |
| **2. Claude の判定を足す** | 第 2 段の総合判断を追加。段階 0 の正解データで「人の判定と一致するか」を確認 | 一致率 8 割を目標 |
| **3. Keepa と振り返り** | Keepa API 契約、月販推定を実数に。リアクション記録と週次レポート | しきい値を自分の実績で調整できる |
| **4. 朝レポート自動化** | Claude Code の Routine で毎朝 7:00 に「今日狙うもの 5 件」をまとめる | grok-bot.md の ⑤ が完全自動になる |

段階 1 までは Keepa も Claude も不要。SP-API（出品者アカウントがあれば無料）だけで動く。

## 5. 必要なもの

| もの | 状態 | 備考 |
|---|---|---|
| Discord bot の稼働場所 | 自宅 PC で在庫ボットが動いている | 同じプロセスに載せる |
| Amazon SP-API の認証情報 | `.env` に項目あり、未設定 | 出品者アカウントで自分用アプリを作る。価格と手数料見積に必須 |
| Keepa API キー | `.env` に項目あり、未設定 | 有料。段階 3 から |
| Anthropic API キー | 未設定 | 段階 2 から |
| Grok の出力を Discord に流す手順 | 手動コピペから始める | Grok 側に自動投稿の口ができれば置き換え |

## 6. 決めること

| 項目 | 案 | 決定 |
|---|---|---|
| 判定しきい値（利益率 / 粗利 / 月販） | 15% / 1,000 円 / 10 個（grok-bot.md 踏襲） | |
| ルールと Claude が食い違ったとき | 保留に倒す | |
| 想定売値の基準 | FBA 新品最安。中古は別判定 | |
| 仕入れ値が不明な投稿 | 定価を仮置きして「仕入れ値要確認」 | |
| 1 日の判定件数の上限 | 50 件（超えたら信頼度 A・B のみ） | |
| 段階 0 の期間 | 1 週間 | |
| Grok 出力の投稿方法 | 手動コピペで開始 | |
